# V26.3.12 — CANONICAL HYDRATION / INDEX REBUILD / AUTHORITATIVE HISTORICAL AUDIT

Surgical fix over V26.3.11.

## Root cause fixed
The V26.3.11 `authoritative_audit()` path called canonical hydration and index rebuild with `session_state=None`. On a Streamlit rerun, the in-memory `ConversationRecord` could therefore contain only the current Message/Request/Round even when the complete application-owned canonical record still existed in the session transport.

## V26.3.12 fix
- `authoritative_audit(chat, session_state)` now hydrates the canonical ConversationRecord from the application-owned session transport itself before rebuilding indexes.
- Runtime indexes are rebuilt only from the hydrated canonical record.
- No fallback from current Request, `request_records`, latest Round, or provider prose can replace canonical history.
- The authoritative historical gate requires exactly two persisted Messages, two Requests, and two distinct RoundRecords for the two-message persistence test.
- Round identity remains an independent immutable `round_id`; `round=1` is only the per-message round number.
- The audit explicitly records the canonical hydration transport and exact-two contract.
- Existing Provider Core, Free Cascade, Secrets, Model Lists, Bridge logic, and Security Audit are unchanged.
