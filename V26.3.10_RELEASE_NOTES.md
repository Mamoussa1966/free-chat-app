# V26.3.10 — Canonical Lifecycle Monotonic Commit / Hydration / Index Rebuild

This release is based directly on V26.3.8.

Core correction:
- Canonical ConversationRecord is append/merge authoritative.
- A current/narrow runtime record can never overwrite historical canonical records.
- Commit merges the previously committed canonical snapshot before publishing.
- Hydration restores the full canonical history before audit.
- Current request ledgers are projections/corroboration, never historical authority.
- Provider Core, Free Cascade, Secrets, and model lists are unchanged.

Required lifecycle:
Message → Request → Round → canonical COMMIT → provider → mutation COMMIT → rerun → hydrate → rebuild indexes → audit.
