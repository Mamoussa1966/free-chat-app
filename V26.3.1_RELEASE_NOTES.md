# V26.3.1 — AUTHORITATIVE CONVERSATION PERSISTENCE

Scope: Conversation Runtime Persistence / State Hydration only.

## Core correction
`v26_3_conversation_persistence` is now the authoritative historical identity source for the V26.3.1 audit.

The authoritative chain is:

`Conversation → MessageRecord → RequestRecord → RoundRecord`

The audit reads the persisted application-owned conversation bucket first. Current/narrower ledgers may corroborate runtime metrics but cannot replace, collapse, or hide historical records already present in the V26.3.1 persistence store.

## Gates
- Message IDs are accepted only from application-owned persistence records.
- Request IDs are accepted only from application-owned persistence records.
- Round IDs are accepted only from application-owned persistence records.
- No IDs are generated by the audit.
- Missing evidence => `NOT_PROVEN`.
- Conflicting Message→Request bindings remain explicit conflicts.
- `HISTORICAL_REQUEST_COUNT` is sourced from the authoritative persistence bucket.
- `MESSAGE_1 → REQUEST_1` and `MESSAGE_2 → REQUEST_2` are evaluated from that same bucket.
- A narrower current ledger cannot reduce a two-request historical persistence store to one request.

## Preserved
Provider Core, Free Cascade, official API-only contract, model lists, Secrets handling, execution accounting, HOTFIX131 prose isolation, and Transactional Bridge implementation are unchanged by this scoped fix.
