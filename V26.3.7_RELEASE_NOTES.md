# V26.3.7 — CANONICAL CONVERSATION STORE LIFECYCLE PERSISTENCE / HYDRATION FIX

## Scope
Fix the actual Conversation lifecycle persistence path. This release does **not** add another audit layer and does not modify Provider Core, Free Cascade, Secrets, or Model Lists.

## Lifecycle contract
```text
create_conversation()
  ↓
create_message()
  ↓
create_request()
  ↓
create_round()
  ↓
COMMIT CANONICAL CONVERSATION RECORD
  ↓
provider execution
  ↓
COMMIT mutations
  ↓
Streamlit rerun
  ↓
HYDRATE CANONICAL RECORD
  ↓
rebuild runtime indexes
  ↓
Historical Audit
```

## Changes
- Added explicit canonical ConversationRecord commit/checkpoint in `conversation_store.py`.
- Added canonical record hydration before runtime/audit use.
- Message registration commits canonical identity immediately.
- Round creation and completion commit canonical identity immediately.
- Request creation commits Message→Request identity before provider execution.
- Streamlit active-chat hydration restores the complete canonical record before narrower ledgers are consulted.
- The historical audit continues to consume the canonical ConversationRecord and cannot replace it with the current Request.
- Session State is only the rerun transport/checkpoint; it is not an audit source.
- Existing identities are merged by immutable IDs; conflicting bindings are preserved as conflicts rather than silently replaced.

## Preserved
- Provider Core unchanged.
- Free Cascade unchanged.
- Secrets/model configuration unchanged.
- No Local Engine.
- No Paid fallback.
- No Dynamic Model Discovery.
- All V26.3.5 files retained; this is additive.
