# V26.2 — MESSAGE LEDGER PERSISTENCE + HISTORICAL IDENTITY GATE

Scope: Message Runtime persistence/reconciliation and authoritative historical audit only.

Preserved unchanged in scope: Provider Core, Free Cascade, model lists, Secrets handling,
HOTFIX131 prose isolation, and Transactional Bridge implementation.

## V26.2 changes
- Primary historical message source is the persisted HOTFIX145 conversation message ledger.
- Every user message must have an application-owned message_id and an explicit request_id.
- The request_id must resolve to a persisted REQUEST_RECORD whose message_id matches exactly.
- V26 message ledger records are reconstructed from persisted application records, never agent prose.
- Conflicting message/request bindings are surfaced as identity_conflict rather than overwritten.
- Historical audit exposes MESSAGE_ID_1/2, REQUEST_ID_1/2, ROUND_ID_1/2 and their mappings.
- Audit exposes message_ledger_source and message_ledger_count.
- Previous-request reexecution and two-message isolation are NOT_PROVEN unless the required persisted chain exists.
- No synthetic IDs are generated by the audit/reconciliation layer.
