# V26.3.4 — CANONICAL CONVERSATION HYDRATION / HISTORICAL IDENTITY

Built from V26.3.3.

## Root-cause fix
The historical audit was canonical-object-only, but the persistence snapshot did not capture the full HOTFIX145 application-owned `chat["messages"]` history when the narrower request ledger contained only the current Request. V26.3.4 persists explicit user Message identity from the canonical Conversation object and binds it to already-existing application-owned Request and Round records.

## Invariants
- `conversation_record.v26_3_conversation_persistence` remains the sole authoritative historical source.
- `session_state` is mirror/compatibility only.
- No provider prose is read for identity or counters.
- No IDs are minted by persistence; real round IDs are copied only from `chat["round_ledger"]`.
- Provider Core, Free Cascade, Secrets, Model Lists and Bridge logic are untouched.
- Historical narrowing is never allowed to overwrite canonical history.

## Regression coverage
- Canonical two-message history survives a current-only request ledger.
- Message→Request mappings remain application-owned.
- Missing round records remain missing; no synthetic round IDs are generated.
