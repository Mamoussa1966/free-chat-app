# V26.3.5 — CANONICAL CONVERSATION STORE PERSISTENCE / HISTORICAL IDENTITY GATE

## Scope
- Built directly from the V26.3.4 source ZIP.
- Preserves Provider Core, Free Cascade, Secrets, and Model Lists.
- No provider-selection or cascade-policy changes.

## Root-cause correction
V26.3.4 still had a split persistence design: historical identity lived in a V26-specific subtree and the audit could observe a narrower/current lifecycle view after reruns.

V26.3.5 makes the HOTFIX145 `ConversationRecord` itself the canonical owner of historical collections:

`ConversationRecord.messages[]`
`ConversationRecord.requests[]`
`ConversationRecord.rounds[]`

The V26 persistence namespace is now an exact compatibility alias to those same lists, not a second source of truth.

## Lifecycle correction
`persist_identity()` is now the canonical Message/Request/Round upsert used at lifecycle points already present in the runtime. It writes immediately; the historical audit no longer needs to reconstruct identity from current ledgers.

## Hydration correction
Hydration reads the canonical ConversationRecord collections and repopulates the transient HOTFIX145 ledgers. A legacy V26.3.x bucket is used only as a one-time migration source when the canonical collection is empty.

## Historical Audit correction
The authoritative audit reads only `HOTFIX145_CONVERSATION_RECORD` for historical Message/Request/Round identity.

It exposes:
- `MESSAGE_ID_1`, `MESSAGE_ID_2`
- `REQUEST_ID_1`, `REQUEST_ID_2`
- per-message Round IDs
- `HISTORICAL_MESSAGE_COUNT`
- `HISTORICAL_REQUEST_COUNT`
- `HISTORICAL_ROUND_COUNT`
- `HISTORICAL_SOURCE`
- `AUTHORITATIVE_SOURCE`

If the canonical historical record contains two Requests while the current/narrow ledger contains one, the audit reports `historical_narrowing_conflict=true` and does not collapse history to the current Request.

Missing identity remains `NOT_PROVEN`; no IDs are generated by the audit and Agent Prose is never used as identity/counter evidence.
