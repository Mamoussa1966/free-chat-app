# V26.3.13 — ROUND IDENTITY LIFECYCLE / CANONICAL REBUILD HARDENING

Base: V26.3.12

Scope: Conversation Persistence / Hydration / Index Rebuild only.

## Root fix
- Critical Message→Request→Round lifecycle writes now pass Streamlit session state through `begin_round()` and `finish_round()` so RoundRecords are committed to the canonical transport at the actual lifecycle boundary.
- `rebuild_runtime_indexes_from_canonical()` now performs a true replacement rebuild from canonical history instead of merging the current/narrow runtime indexes with canonical history.
- Historical narrowing conflict is captured from the pre-rebuild current index state, before rebuild intentionally restores the complete canonical history.

## Round identity contract
Each Request's Round 1 receives an independent immutable `round_id`:
`<conversation_id>:<request_id>:r1`

Therefore two Messages in one Conversation have two distinct Round IDs even when both have `round_number=1`.

## Regression proof
The new regression test executes:
Request 1 → Round ID A → commit
RERUN / narrow current runtime
Request 2 → Round ID B → commit
HYDRATE → REBUILD INDEXES → AUTHORITATIVE AUDIT

Required assertions:
- HISTORICAL_MESSAGE_COUNT = 2
- HISTORICAL_REQUEST_COUNT = 2
- HISTORICAL_ROUND_COUNT = 2
- MESSAGE_1 → REQUEST_1 = PASS
- MESSAGE_2 → REQUEST_2 = PASS
- REQUEST_1 → ROUND_1 = PASS
- REQUEST_2 → ROUND_1 = PASS
- ROUND_ID_1 != ROUND_ID_2
- PREVIOUS_REQUEST_REEXECUTED = NO
- TWO_MESSAGE_ISOLATION = PASS

No changes to Provider Core, Free Cascade, Secrets, Model Lists, Bridge, or Security Audit.
