# V26.3.3 — CANONICAL CONVERSATION RECORD PERSISTENCE

Fixes the V26.3.2 failure where the historical ledger could exist only in a transient/session mirror while the authoritative audit saw only the current Request.

## Canonical source
`chat["conversation_record"]["v26_3_conversation_persistence"][conversation_id]` is now the sole authoritative historical identity store. It is part of the canonical Conversation object contained in the conversation collection.

## Rules
- Message → Request is persisted before provider dispatch.
- Round → Message → Request is persisted before/after execution.
- Rerun/hydration reads the canonical Conversation object.
- `st.session_state["v26_3_conversation_persistence"]` is not an authoritative fallback.
- Missing canonical history remains NOT_PROVEN.
- Legacy top-level `chat["v26_3_conversation_persistence"]` is compatibility-only.
- Provider Core, Free Cascade, Secrets, Model Lists, and Bridge behavior are unchanged.
- No files are removed.
